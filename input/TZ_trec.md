# Техническое задание
## Канбан-доска производственных этапов

**Версия:** 1.0 | **Статус:** на согласование заказчику | **Платформа:** веб-приложение (PHP), деплой на Railway

---

## 1. Цель проекта

Разработать внутренний инструмент визуального контроля производственных проектов. Система показывает, на каком этапе находится каждая из 4 рабочих задач каждого проекта, фиксирует даты перемещений и ответственных, позволяет обсуждать задачи в комментариях.

**Результат MVP:** работающее веб-приложение, развёрнутое на Railway, с фиксированной структурой «4 задачи × 5 этапов», рассчитанное на команду до 20 человек и до 10–20 одновременных проектов.

**Ключевая особенность доски (согласовано):** строка = проект, столбцы = 5 этапов, при этом **все 4 задачи проекта видны в каждом этапе**. Доска работает как матрица статусов: карточка задачи в каждом этапе имеет своё состояние (ожидание / в работе / завершено). Возможна параллельная работа задачи в нескольких этапах одновременно.

---

## 2. Роли пользователей и права

Роли две: **Руководитель** и **Сотрудник**.

| Действие | Сотрудник | Руководитель |
|---|---|---|
| Просмотр доски, проектов, истории перемещений, комментариев | ✅ | ✅ |
| Перемещение **своей** задачи между любыми этапами | ✅ | ✅ |
| Перемещение чужих задач | ❌ | ✅ |
| Комментарии к **своей** задаче | ✅ | ✅ |
| Комментарии к чужим задачам | ❌ (только чтение) | ✅ |
| Создание / редактирование / архивация проектов | ❌ | ✅ |
| Управление пользователями (создание, деактивация) | ❌ | ✅ |
| Смена собственного пароля | ✅ | ✅ |

*«Своя задача» = пользователь назначен ответственным за эту задачу в данном проекте.*

## 3. Авторизация и управление пользователями

- Вход по email + пароль. **Самостоятельной регистрации нет** — аккаунты создаёт Руководитель вручную.
- Деактивированный пользователь не может войти, но остаётся в истории перемещений, комментариях и выпадающих списках (жёсткое удаление не предусмотрено — сохраняем целостность истории).
- **Экран «Пользователи» (только Руководитель):** таблица (имя, email, роль, статус, дата создания), создание (имя, email уникальный, пароль ≥ 8 символов, роль), редактирование, деактивация/активация, сброс пароля вручную. Восстановление пароля по email в MVP не входит (упрощает деплой).
- Первый пользователь — Руководитель, создаётся при наполнении базы демо-данными.
- Профиль: смена собственного пароля (текущий + новый).

## 5. Экраны и функции

### 5.1. Экран входа
Логотип, email, пароль, кнопка «Войти», ошибка при неверных данных. После входа — редирект на доску.

### 5.2. Доска (главный экран)

**Шапка:** логотип, поиск, фильтры, кнопка «Новый проект» (Руководитель), меню пользователя.

**Фильтры и поиск (в MVP):**
- поиск по названию проекта;
- фильтр по ответственному (любая из 4 задач проекта);
- фильтр по статусу проекта;
- переключатель «Активные / Архив»;
- чекбокс «Только просроченные».

**Структура доски:** таблица. Строка = проект (название, даты старта/завершения, бейдж статуса). Колонка с названием проекта — закреплена при горизонтальном скролле. Далее 5 колонок этапов; в каждой ячейке — 4 мини-карточки задач.

**Состояния карточки задачи в этапе:**
| Состояние | Вид | Дата над карточкой |
|---|---|---|
| Ожидание | серая, приглушённая | нет |
| В работе | акцентная рамка/заливка | **да** — дата входа в этап (ДД.ММ) |
| Завершено | зелёная галочка, компактно | нет |

Параллельная работа: несколько карточек одной задачи могут быть одновременно «В работе», каждая со своей датой.

**Перемещение (desktop/tablet):** drag-n-drop карточки со статусом «В работе» в любую колонку этапа. При drop:
- целевой этап → «В работе», дата входа = сейчас, запись в историю;
- поповер над исходным этапом: «Завершить этап [название]?» → **[Завершить]** / **[Оставить в работе]** (параллельный режим);
- возврат на пройденный этап разрешён (этап снова «В работе»).

**Перемещение (mobile / альтернатива мыши):** меню ⋮ на карточке: «Перенести на этап…» (список этапов), «Завершить этап», «Открыть карточку». Логика и история — те же.

**История:** клик по карточке/дате → модалка задачи, вкладка «История» — полный журнал в обратном хронологическом порядке: дата-время (ДД.ММ.ГГГГ ЧЧ:ММ), автор, событие («Этап начат / завершён / возвращён в работу», откуда → куда).

**Подсветка сроков:** бейдж у даты завершения активного проекта: красный «Просрочен на N дн.», жёлтый «Осталось N дн.» (порог 3 дня). Для «Завершён / Отменён / Архив» подсветка не действует.

**Статусы проекта:** Активен / Приостановлен / Завершён / Отменён + флаг «В архиве». Архив скрыт с основной доски, доступен через фильтр «Архив», доступен только для чтения, восстанавливаем. «Приостановлен» — визуальная метка, действия не блокируются *(упрощение MVP — см. п. 13)*.

### 5.3. Модалка «Проект» (создание / редактирование — Руководитель)
Поля: название* (до 100 симв.), дата старта*, желаемая дата завершения* (≥ старта), ответственный для каждой из 4 задач* (select из активных пользователей; один человек может отвечать за несколько задач). Редактирование — те же поля + статус. Валидация с подсветкой ошибок.

### 5.4. Модалка «Задача»
Заголовок: проект + задача + ответственный. Три вкладки:
- **Этапы:** 5 строк со статусами и кнопками управления (для ответственного и Руководителя);
- **История:** журнал перемещений;
- **Комментарии:** лента (аватар, имя, дата, текст) + поле ввода. Пишут — ответственный и Руководитель, видят — все. Своё сообщение может удалить автор; Руководитель — любое. Вложения — вне MVP.

### 5.5. Экран «Пользователи» — см. раздел 3.

## 8. Технические требования

- **Стек:** Laravel 11 (PHP 8.3), SQLite, Blade-шаблоны. Фронтенд-библиотеки через CDN: Tailwind CDN + Alpine.js CDN + SortableJS CDN. 
Сборка фронтенда не используется (zero-build). 
Аутентификация — самописные сессии Laravel (Auth facade), login only. Роли — поле role + Policies (роли через колонку role + Gate). 
Запуск: composer install → php artisan migrate --seed → artisan serve
Деплой: Railway, один сервис
- **Безопасность:** bcrypt, CSRF, проверка прав на сервере (Policies), валидация всех входных данных, авторизация обязательна на всех страницах. HTTPS — средствами Railway.
- **Целостность данных:** перемещение + запись в историю — в одной транзакции.
- **Производительность:** загрузка доски ≤ 3 с при 10 проектах (20 ячеек × 10 строк), без N+1.
- **Часовой пояс:** UTC+3 (МСК), формат дат ДД.ММ.ГГГГ, в истории — с временем.
- **Демо-данные (seed):** 5–6 пользователей (1 руководитель), 3 проекта на разных стадиях, включая параллельные этапы и просроченный проект.

## 9. Что НЕ входит в MVP (этап 2)

Вложения в комментариях · уведомления (email/Telegram: о комментариях, переносах, дедлайнах) · отчёты и экспорт в Excel · админ-CRUD задач/этапов · интеграции.

**Архитектура готова к этапу 2:** этапы/задачи — в таблицах БД; журнал перемещений — основа для отчётов; комментарии — сущность, к которой добавляются файлы.

## 10. Критерии готовности MVP

**Авторизация**
- [ ] вход по email/паролю; неверные данные — ошибка; неавторизованный — редирект на вход
- [ ] деактивированный пользователь войти не может

**Проекты**
- [ ] Руководитель создаёт проект со всеми полями; валидация дат и обязательных полей работает
- [ ] Сотрудник не видит кнопку создания; прямой запрос к API → 403
- [ ] архивация скрывает проект с доски, доступна через фильтр «Архив», восстановление работает

**Доска**
- [ ] матрица: проекты × 5 этапов × 4 задачи, состояния карточек корректны
- [ ] drag-n-drop переносит задачу; дата над карточкой обновляется и сохраняется после F5
- [ ] параллельные этапы: две активные карточки с датами одновременно
- [ ] свободный перенос в любой этап, в т.ч. назад — работает
- [ ] история: полный журнал с автором и датой-временем каждого события

**Комментарии и права**
- [ ] пишут только ответственный и Руководитель, видят все
- [ ] Сотрудник не может переместить/прокомментировать чужую задачу

**Сроки и фильтры**
- [ ] просрочка — красный бейдж, ≤ 3 дней — жёлтый
- [ ] поиск и все фильтры работают

**Адаптивность**
- [ ] проверено на 1920 / 1366 / iPad / iPhone; на мобильном перемещение через меню

## 12. Допущения — требуется подтверждение заказчика

1. **Кол-во пользователей** (п. 2.1 анкеты без ответа) — принято «до 50».
2. **Уведомления о дедлайнах** (5.3 — «да», 4.4 — «позже»): в MVP — только визуальная подсветка; email-уведомления — этап 2.
3. **«Приостановлен»** не блокирует перемещения — только метка.
4. **Названия задач и этапов** придуманы исполнителем — заменить на финальные до старта.
5. Удаление пользователей и проектов не предусмотрено (только деактивация/архив) — для сохранения истории.
6. Комментарии привязаны к задаче проекта в целом, а не к конкретному этапу.
